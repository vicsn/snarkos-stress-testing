# Client Node Sync Runner

## Prerequisites

- [Install Terraform](https://developer.hashicorp.com/terraform/downloads?product_intent=terraform)
    - `brew tap hashicorp/tap`
    - `brew install hashicorp/tap/terraform`
- [Install Ansible](https://docs.ansible.com/ansible/latest/installation_guide/intro_installation.html#installing-and-upgrading-ansible-with-pip)
    - `brew install ansible`
- [Install AWS CLI](https://aws.amazon.com/cli/)
    - `brew install awscli`
- Make sure you have access to github.com/ProvableHQ/snarkos-staging
- You can build binaries with github actions or use the local cross-compilation method and use AWS S3 for release distribution. To use the local build method, run these steps first on Mac:
    - `brew tap SergioBenitez/osxct`
    - `brew install x86_64-unknown-linux-gnu`
    - `brew install openssl@3` (this should create a folder `/opt/homebrew/Cellar/openssl@3/3.4.0`. In case newer versions are released, update the version in the file `playbooks/roles/snarkos_build_locally/defaults/main.yml` and try it out.)
    - `rustup target add x86_64-unknown-linux-gnu`

The local build method uses the S3 bucket `release-bucket-2122415`, which been created on AWS using the command `aws s3api create-bucket --bucket release-bucket --region us-east-1`. By default in the `vars.example.yml` file, it compiles snarkOS with the `test_targets` feature (lowering the coinbase proving target, tx cannon needs to be compiled with the `enable_test_targets` feature alongside) and the `test_skip_tx_checks` feature (allows for fake txs to be processed, only exists for the `malice` snarkOS branches.)

## Using the `check_sync.sh` script to monitor node sync progress.

The script `check_sync.sh` polls each client’s `/<network>/block/latest` endpoint and **persists** per-height state in `playbooks/network_info.json`, so it can **resume** after restarts.
Writes are **atomic** and pretty-printed; a lock prevents concurrent writers.
Works on macOS and Ubuntu 22+.

### Requirements

- Bash
- `jq`, `curl`

Install:
```bash
# Ubuntu
sudo apt-get update && sudo apt-get install -y jq curl

# macOS (Homebrew)
brew install jq
```

### Input JSON format

`playbooks/network_info.json` should look like:

```json
{
  "0":        { "url": "54.149.140.211" },
  "1000000":  { "url": "34.217.31.18" },
  "2000000":  { "url": "52.25.57.134" },
  "3000000":  { "url": "54.213.88.179" },
  "4000000":  { "url": "34.213.13.112" }
}
```

This file is generated by running `run_client_sync_test.sh` and has the right IPs of the clients for the right starting heights.

On first run, the script auto-initializes missing per-height fields:
- `previous_height` ← the key’s numeric height, starts from the initial snapshot height (or 0 if no snapshot is used) (e.g., `3000000`)
- `status` ← `"running"`
- `timestamp` ← set the first time we observe the entry (see rules below)

The script also writes `current_height` whenever a probe succeeds.

### Usage

```bash
./check_sync.sh [-f JSON_FILE] [-i MINUTES] [-t TIMEOUT] [-w SECONDS] [-S SECONDS] [-D DELTA] [-O] [-v]
```

#### Options

- `-f` Path to JSON file (default: `./playbooks/network_info.json`)
- `-i` Minutes between checks (default: `1`)
- `-t` `curl` max-time per endpoint (seconds, default: `6`; connect timeout is `3s`)
- `-w` Seconds to fail when endpoint is **unavailable** or `current < initial`
  - default: **7200** (2h)
- `-S` Seconds to fail when **no progress** (stall window)
  - default: **600** (10m)
- `-D` Success delta from **initial** height to declare **success**
  - default: **1000000**
- `-O` Run **once** and exit (good for CI/one-shot checks)
- `-v` Verbose (enables `bash -x` tracing)

#### Exit codes (with `-O`)

- `0` — all entries **success**
- `1` — all entries **failed**
- other — mixed/ongoing (in loop mode the script doesn’t exit)

### Sync rules (per height)

- **Unavailable endpoint** → `status="waiting"`.
  - If `timestamp` is missing, set it now.
  - If `now - timestamp >= -w`, mark **failed**.
- **`current_height < initial`** → `status="waiting"` (uses same `-w` failure rule).
- **`current_height > initial + D`** → mark **success** and stop checking this height.
- **Progress (`current > previous_height`)** → `status="running"`;
  - set `previous_height = current_height` and update `timestamp`.
- **No progress (`current <= previous_height`)** → `status="waiting"`;
  - do **not** update `timestamp`.
  - If `now - timestamp >= -S`, mark **failed**.
- Entries already **failed** or **success** are skipped in later iterations.

### Examples

Run once, faster probes, custom thresholds:
```bash
./check_sync.sh -f playbooks/network_info.json -O -t 3 -S 300 -w 5400 -D 800000
```

Continuous monitoring with defaults:
```bash
./check_sync.sh -f playbooks/network_info.json
```

Verbose trace (debug):
```bash
./check_sync.sh -f playbooks/network_info.json -O -t 3 -v
```

### Operational details

- **Single-writer lock**: creates `<JSON_FILE>.lockdir`. If you see
  `Another instance appears to be running (lock: ...)`, stop the other run (or remove the lock **only** if you’re sure nothing else is running).
- **Atomic, pretty JSON writes**: updates go through a hidden temp (e.g., `.<name>.tmp.xxxxx`) then `mv` into place; leftover temps from prior runs are cleared at startup.
- **macOS & Ubuntu 22**: macOS uses `date -j` if GNU `date` isn’t present; Ubuntu uses GNU `date`.
